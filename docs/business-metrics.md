# Business and platform metrics

The demo makes the operational consequences of data quality visible without
inventing production results. All numbers generated by the project are synthetic.

| Metric | Definition | Decision it supports |
| --- | --- | --- |
| Freshness | Age of the newest accepted event | Whether dashboards can be trusted |
| Completeness | Accepted records divided by expected records | Whether a source needs investigation |
| Duplicate rate | Repeated event keys divided by landed records | Whether replay/idempotency is healthy |
| Pipeline latency | Time from landing to gold publication | Batch SLA and capacity planning |
| Data incident MTTR | Time from quality alert to validated rerun | Reliability of operational response |

For a real client, baseline values, SLA targets and cost per run must be measured from
production telemetry. The portfolio should report those values only after they are
verified and approved for disclosure.
